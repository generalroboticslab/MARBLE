# Provenance

This repository is a fresh-history public release, assembled from two internal
General Robotics Lab repositories by copying cleaned file trees. The internal
history is not published.

## Sources

| Directory here | Internal repository | Branch | Commit |
|---|---|---|---|
| everything except `hardware_bindings/`, `simulation/`, `media/` and `cad/` | ballbot_control | `CAN_rework` | `401d29a14e05e3287c25f97f9496d889925c85c2` |
| `hardware_bindings/` | hardware_bindings | `ballbot` | `06d9f5e581b3dbc43382254591f45bf441aef403` |
| `simulation/` | legged_env_v2 (training) | `master` | generated by its `scripts/make_marble_sim.py` |

The documentation, `LICENSE`, `CITATION.cff`, `.gitattributes`, this file and
the EasyProfile `NOTICE.md` are new. Kept files lost commented-out code and
unused functions; apart from the removals below, control behaviour is
unchanged.

`hardware_bindings/` inlines only the IMU extension of a private submodule
shared by several lab robots, with unused code (`FakeIMU`, a getter, the NNG
publisher classes) removed and the build files cut to match.
`imu/EasyProfile/` is byte-identical to the internal copy.

`cad/MarbleASM.step.zip` is the robot's CAD assembly as STEP. It
includes vendor models of purchased parts (GL40 II motors, the XIAO board and
its CAN breakout, electronics, fasteners); those keep their vendors' terms.

## Motor IDs

The release uses CAN IDs `0x08`, `0x07` and `0x06` (`MOTOR_IDS` in
`src/ballbot_runtime.py`), and the bridge firmware matches
([`docs/FLASH_XIAO.md`](docs/FLASH_XIAO.md)).

`config/calibration.robot-backup.json` was recorded on the old ID set (`0x03`,
`0x04`, `0x06`); its IDs were rewritten to `0x08`, `0x07`, `0x06` in
`JOINT_NAMES` order with the signs carried over, so it may not match a robot's
wiring. Calibrate before the first control run
([`docs/SETUP.md`](docs/SETUP.md#slider-calibration)).

## The shipped checkpoints

The six `policy_deployed.pt` archives are the internal copies with
TorchScript's `*.debug_pkl` entries (training-machine paths and source text)
removed. Weights and compiled code are byte-identical and outputs match; the
md5s in [`policies/README.md`](policies/README.md#checksums) differ from the
internal copies.

Each `robot.xml` references meshes from the training asset tree (STL, plus one
OBJ in four of them) and, in those four, `textures/carbon_fiber_plain_spec.png`.
These are not redistributed, so `robot.xml` does not compile in MuJoCo from
this repository. The runtime reads only `env_config.yaml`;
`scripts/policy_sim_check.py` needs the meshes and texture. The wire mesh is
referenced as `meshes/wire_1_Body1.stl`, which differs from its file name in
the training asset tree; rename that file to match.

## Third-party components

Only EasyProfile is redistributed; everything else is fetched at setup under
its own licence. Versions are unpinned except the two Arduino packages in
[`docs/FLASH_XIAO.md`](docs/FLASH_XIAO.md).

| Component | Use | Source | Licence |
|---|---|---|---|
| SYD Dynamics EasyProfile 1.1.9 (R) | IMU serial protocol; code adapted into `hardware_bindings/imu/imu.hpp` | `hardware_bindings/imu/EasyProfile/` | BSD-2-Clause; see [`NOTICE.md`](hardware_bindings/imu/EasyProfile/NOTICE.md) |
| nanobind | Python binding of the IMU driver | pip | BSD-3-Clause |
| Eigen3 | Linear algebra in the IMU driver | vcpkg | MPL-2.0 |
| CSerialPort (itas109) | Serial port in the IMU driver | vcpkg | LGPL-3.0 with a linking exception |
| fmt | Linked into the IMU extension | vcpkg | MIT |
| Seeed nRF52 Boards (`Seeeduino:nrf52`) | Board package for the XIAO bridge firmware | Seeed Arduino board index | LGPL-2.1-or-later; not redistributed |
| `mcp_canbus` (Longan Labs) | MCP2515 driver in the firmware | https://github.com/Longan-Labs/Arduino_CAN_BUS_MCP2515 | MIT |
| Python packages | Runtime, tools, offline checks | PyPI: `config/requirements-robot.txt` | Each its own |
| PyTorch | Running trained policies | Installed separately | BSD-3-Clause, plus bundled components |
